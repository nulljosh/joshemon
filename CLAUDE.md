# Joshemon

A monster-collecting RPG for the Game Boy Advance, written in C. It looks and plays like Pokemon Sapphire, with its own 105 creatures, world, story and chiptune. Moves, the type chart and the numbers each creature borrows come from Gen 3 data (PokeAPI). Public since 2026-11-02 at Joshua's call: repo nulljosh/joshemon (MIT, with a not-affiliated note in the README), releases carry the .gba, and the landing in `web/` serves joshemon.jaybulb.com (`./deploy.sh` rebuilds the ROM and runs `wrangler deploy`). The title shows JOSHÉMON. There is no JavaScript left; the old JS build sits in `~/Documents/Code/_attic/joshemon-js/` and is not used.

## Build
- `cd gba && make`: builds the painter (`tools/paint.c`, host cc), paints every map and person into `build/maps.c`, then compiles the cartridge to `build/joshemon.gba` with arm-none-eabi-gcc (brew). Play it in mGBA.
- `make test`: the Gen 3 rules (`src/rules.c`) against hand-worked values.
- `make build/gbarun`: the headless runner (libmgba from brew). `build/gbarun ROM SCRIPT SHOTDIR [out.wav [out.raw]]` follows a key script (`wait N`, `press A+UP N`, `shot NAME`) and writes screenshots, sound and every frame. Each run starts with an empty save in memory, so nothing a script saves carries over to the next run. Within a run, `reset` power-cycles and keeps the save, and `corrupt HEXOFF` flips a save byte the way a cut write would (script sv1). For long videos, hand it a fifo as the raw file and let ffmpeg read the other end. SHOTDIR must exist. Turn the raw frames and wav into a video with `ffmpeg -f rawvideo -pix_fmt rgb24 -s 240x160 -r 59.7275 -i out.raw -i out.wav -vf scale=720:480:flags=neighbor -c:v libx264 -pix_fmt yuv420p -c:a aac out.mp4`.
- `python3 tools/compose.py` (make runs it) writes the songs from `music/songs*.py` to `build/songs.inc`. `make build/qa_juke.gba` plays every song in turn for a listening render.
- `tools/regress.sh` builds the ROMs and plays all 29 regression scripts (screens in `build/reg/`). Every line has to read 0. QA builds give the lead a full heal before each trainer battle, so scripts test the story, not the dice. `make build/qa_fx.gba` plays every type's move effect at the first battle.
- QA start: hold L+R with START on the title for a new game with a L5 starter (skips the intro). Builds with `-DQA_FIELD` (every badge, BIKE, rod, at HARBOR) and `-DQA_EVO` (one EXP short of evolving) exist for field skills and evolution tests.

## File size
A global pre-commit hook blocks any text file over about 5000 tokens (20 KB), so the big files are cut into parts. The parent includes its parts in order, so the compiler sees one file. These are `data/world.c` with `data/parts/world_N.inc`, `data/dex.c` with `dex_N.inc`, `tools/paint.c` with `tools/parts/paint_N.inc`, and `src/main.c`, `battle.inc`, `menus.inc` and `story.inc` with `src/<name>_N.inc`, plus `src/battle_team.inc` (team screen) and `src/battle_fx.inc` (move effects). Add new maps to the last world part, and start a new part when one nears 18 KB. The baked art tables are kept as `data/art.c.gz`: make unpacks them to `build/art.c`, and `tools/legend.py` edits the gzip. Songs come from `music/songs.py` and `songs2.py`, and make writes them to `build/songs.inc`.

## Layout
- `gba/data/world.c` + `world.h`: the world, edited by hand. Maps are rows of tile letters (the legend is at the top of world.h), warps, signs, people (`N_` arrays: place, look, lines, trainer, conditions as flag lists), trainers, line sets (`L` arrays), items, story flags (`FLAG_*`), the FLY table, people's looks for the painter.
- `gba/data/dex.c`: the 105 creatures (names, dex lines, types, stats, learnsets, evolutions), every Gen 3 move, the type chart. `gba/data/art.c.gz`: creature art (front and back), the four battle scenes, the title picture, baked once from the old painter; the late legends after #105 are drawn by `tools/legend.py`, which writes them into art.c.gz. `gba/data/font.h`: Adafruit GFX 5x7 font (BSD).
- `gba/tools/paint.c`: draws every map (tiles with neighbour-aware edges, trees and canopy, water and flower frames), people, things and trainer portraits, then cuts and packs them for the hardware. It matched the old JS painter pixel for pixel.
- `gba/src/main.c`: the overworld, text surface (BG0 tiles handed out on first touch, drawn by ARM code in IWRAM), dialog, menus, saves (SRAM). `battle.inc` battles, team screen, evolution. `story.inc` trainers and cutscenes. `menus.inc` BAG, DEX, SUMMARY, marts, PC, OPTION, TOWN MAP and FLY, field skills. `sound.inc` the four tone channels plus a software mixer of six sampled instruments on Direct Sound A (samples synthesized by `tools/samples.py`), all run from the VBlank interrupt. `rules.c` the Gen 3 formulas from pret/pokeruby.
- `docs/LOOP-HANDOFF.md`: restart prompt, what is done, what is next. `roadmap.md`: the checklist.
